# 未选择的路 / DecisionPath

一个替人保存决策记忆、让人逐渐看清自己的 iOS App。`DecisionPath` 是内部工作名，产品名尚未定。

**它不替用户选择，也不虚构另一条路的结果。** 它记录用户真实选择过的 A 与 B，以及每次选择之后真实发生的感受。

## 产品循环

1. 用户说出此刻的纠结。
2. AI 把它整理成两条清晰的路。
3. 用户选择一条。
4. App 在约定时间回来询问真实感受。
5. 同类选择积累后，对比 A/B 的选择次数、结果与情绪。

## 三个定义了这个产品的决定

**只在犹豫的时刻产生记录。** 斗志昂扬直接去做的那天不会有记录，累到根本没想过的那天也不会有。样本因此不是「所有日子」，而是一个精确定义的条件样本——恰好是那些真正需要答案的日子。代价是洞察必须显式带上这个条件才成立，收益是它比一个被污染的随机样本准确得多。

**第 1 条记录就必须自己产出价值。** 产品主动放弃了打卡、连续天数、红点和推送式催促，所以没有任何留存手段可以用来「熬到数据够」。解决办法不是降低洞察门槛，而是把预期折进选择的手势里——按住路标向上推一段，既选了 A 也表达了「我以为大概 7 分」。于是第一条记录回访完成时就有了「你以为 4 分，实际 7 分」，不需要统计，不涉及因果，不需要第二条记录。第二次遇到同类纠结时直接复述上一次：n=1 时系统没有资格比较，但有资格记得。

**AI 只负责把纠结拆开，判断留给用户。** 模板命中走本地确定性映射，未命中才路由到云端模型；跨记录分析基于用户自己的历史。洞察语气按样本量分三档——1 条只能陈述、2 条只能并列、≥3 条才允许比较级。这条约束是规则可判的，因此「模型越档」可以被自动检测，等于把「禁止说什么」量化成一个违规率。

## 技术

- **UIKit**：文字输入、状态编排与可访问操作控件
- **SpriteKit**：持续运行的道路、人物行走、景物循环与视差
- **Core Animation**：覆盖层与状态过渡
- 程序化布局，不使用 Storyboard，不引入 SwiftUI —— 连续空间是这个产品的隐喻，页面切换会把它碰碎
- iOS 17+，Swift 5

## 当前状态

首个游戏化原型已跑通一条完整闭环：人物沿左下至右上的道路持续行走 → 用户输入纠结 → 路标出现 → 选择后穿过路标 → 继续前行。

后续优先级：决策记录与回访的数据模型；云端服务协议、隐私说明与错误降级；VoiceOver、动态字体与降低动态效果适配。
